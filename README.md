# LogAnalyser 日志分析工具

一个使用 C++ 编写的命令行日志分析工具。程序读取日志文件，校验每条日志的时间、等级和消息，统计各等级的日志数量及出现次数最多的三种 ERROR 消息，并将分析报告输出到终端和文件。

项目采用 CMake 构建，将日志处理代码封装为静态库 `log_core`，由可执行程序 `app` 调用。当前使用 C++11 标准，不依赖第三方 C++ 库。

## 功能

- 逐行读取日志，提取时间戳、日志等级和消息。
- 去除各字段首尾的空格、制表符等空白。
- 校验日期与时间，包括月份天数、闰年和时分秒范围。
- 支持 `TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`、`FATAL` 六种等级。
- 统计有效日志的等级分布和 ERROR 消息出现次数。
- 输出 Top 3 ERROR 消息，次数相同时按消息字典序排列。
- 提示非法日志及原因，跳过该行并继续读取。
- 将报告同时输出到终端和 `output/report.txt`。

## 编译与运行

下面以 Windows + MinGW 为例。需要安装：

- 支持 C++11 的 G++ 编译器。
- CMake 3.15 或更高版本。
- MinGW Make 工具 `mingw32-make`。

这些工具所在目录需要加入 `PATH`。可在终端检查：

```bash
cmake --version
g++ --version
mingw32-make --version
```

### 1. 进入项目根目录

项目根目录是包含顶层 `CMakeLists.txt` 的目录。例如，在 Git Bash 中：

```bash
cd ~/Desktop/LogAnalyser
```

如果使用 PowerShell：

```powershell
Set-Location 'C:\Users\Resnet\Desktop\LogAnalyser'
```

### 2. 配置与编译

以下命令在项目根目录执行，Git Bash 和 PowerShell 均可使用：

```bash
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
```

构建成功后，可执行文件位于 `bin/app.exe`。修改已有源文件后，可以再次运行 `cmake --build build`；新增源文件后，应重新执行配置命令。

如果已有 `build` 目录使用了其他生成器，可以将以上两条命令中的 `build` 都换成一个新目录名，例如 `build-mingw`，避免混用构建缓存。

### 3. 运行

确认 `logs/system.log` 存在，且 `output` 文件夹已创建。在 Git Bash 中运行：

```bash
./bin/app.exe
```

在 PowerShell 中运行：

```powershell
.\bin\app.exe
```

**请保持当前工作目录为项目根目录，不要先进入 `bin` 再运行。** 程序使用相对于工作目录的路径读取 `logs/system.log`、写入 `output/report.txt`。

## 日志格式

每行一条日志，格式为：

```text
YYYY-MM-DD HH:MM:SS|等级|消息
```

示例：

```text
2026-10-22 09:00:00|INFO|应用启动
2026-10-22 09:00:03|ERROR|数据库连接失败
2026-10-22 09:00:05 | WARN | 磁盘剩余空间不足
2024-02-29 23:59:59|INFO|闰年日期测试通过
```

输入规则：

- 建议保存为 UTF-8 无 BOM 编码；当前程序不移除文件开头的 BOM。
- 时间戳必须符合上述固定格式，年份为 `0001` 至 `9999`，日期必须真实存在。
- 小时范围为 `00` 至 `23`，分钟和秒为 `00` 至 `59`。
- 等级区分大小写，只接受六种大写等级。
- 三个字段去除首尾空白后都不能为空。
- 前两个 `|` 用于分割字段，消息中可以继续包含 `|`。
- 空行也会被计为非法日志；不要在日志中添加说明标题或注释行。

以下日志会被判定为非法：

```text
2026-02-29 09:00:00|INFO|平年不存在二月二十九日
2026-10-22 24:00:00|INFO|小时超出范围
2026-10-22 09:00:00|UNKNOWN|不支持的等级
2026-10-22 09:00:00|ERROR|
这是一条没有分隔符的日志
```

## 统计与输出规则

- 文件总行数为本次读取的有效日志数量与非法日志数量之和。
- 等级统计和错误排行只使用有效日志；没有出现过的等级不会单独显示。
- 只有等级为 `ERROR` 的日志进入错误统计，`FATAL` 单独计数。
- ERROR 消息去除首尾空白后按完整文本分组，不合并措辞不同的消息。
- Top 3 按次数从高到低排列；不足三种时输出全部，没有 ERROR 时提示没有错误日志。
- 非法日志的原文及原因输出到终端的标准错误流，报告文件仅包含分析结果和非法日志总数。
- 每次运行会覆盖 `output/report.txt`，不会追加到旧报告。
- 打开输入文件或报告文件失败、报告写入失败时，程序输出错误信息并以状态码 `1` 退出；正常完成时返回 `0`。存在非法日志本身不会导致程序失败。

## 代码职责

| 模块 | 作用 |
| --- | --- |
| `LogEntry` | 保存单条日志，提供字段访问、有效性检查和 ERROR 判断 |
| `LogReader` | 打开文件、解析日志、去除首尾空白并统计非法行 |
| `LogAnalyzer` | 统计日志等级、计算错误排行并通过输出流生成报告 |
| `app/main.cpp` | 连接读取和分析流程，将报告输出到终端及文件，处理异常 |

处理流程：读取文件 → 分割并校验每行 → 收集有效日志 → 统计等级和错误消息 → 输出报告。

## 常见问题

### 提示 `cmake: command not found`

确认命令拼写是 `cmake`，并检查是否安装 CMake、是否将其可执行文件目录加入 `PATH`。修改环境变量后重新打开终端。

### 提示无法打开日志或报告文件

检查当前工作目录是否为项目根目录，确认 `logs/system.log` 存在且可读、`output` 文件夹存在且可写。程序不会自动创建输出目录。

### 中文显示乱码

确认源文件和日志使用 UTF-8 编码，终端也使用 UTF-8。Windows 控制台可尝试先执行 `chcp.com 65001`。如果日志带有 BOM，请另存为 UTF-8 无 BOM。

## 当前范围

目前输入和输出路径固定写在 `app/main.cpp` 中，尚未支持命令行参数。程序一次将全部有效日志载入内存，适合学习和一般规模的文本日志分析。当前不提供按日期汇总、时间区间筛选、递归读取目录或实时监控功能，也未配置自动化测试目标。
